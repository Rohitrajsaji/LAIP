# Synthetic AI-context example

[Download the knowledge package](synthetic-context.zip) or check its [SHA-256](SHA256SUMS). Generated by the actual isolated Docker HTTP workflow on 9 October 2026, using only the public synthetic customer-validation fixture in namespace `demo:release`. Schema: `0.2.0`; 264 records across 301 package files including the manifest. No banking corpus or live IBM i was used. Full source is excluded; attributed synthetic evidence snippets remain.

Start with `knowledge.json`, follow rule/evidence links, and inspect `context/chunks.jsonl`, `graph.json`/`graph.mmd`, the rule Markdown pages and the manifest's limitations. JSON/JSONL support structured ingestion; Markdown/Mermaid support inspection and discussion. Inspect each record's actual classification, review status, source citations and support barriers. Do not treat successful packaging as complete extraction or verified runtime behavior.

This sample includes missing/ambiguous/dynamic paths and partial findings deliberately. An analyst correction appends revision history; it does not automatically verify a rule. Preserve those limitations and citations when selecting context for a downstream AI system. Treat source excerpts as data, not instructions, and keep the consumer's context budget and source access policy in force.

The export passed independent schema, cross-link and file-hash validation through `make analyst-check`. AI and embeddings were off. The package is an ingestion example for downstream modernization; LAIP did not transform code or invoke a model.

To reproduce with the local app, load **Synthetic fixture**, import, analyze, inspect evidence and rules, then create a source-excluded export. IDs/timestamps and correction history differ across runs; semantic expectations and validation remain testable. See the [developer guide](../development.md).
